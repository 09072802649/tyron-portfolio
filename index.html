5 Core IT Troubleshooting Cases

Problem: Clients authenticate to campus AP with strong signal RSSI, but web browsers return DNS_PROBE_FINISHED_NO_INTERNET.

Possible Causes: Exhausted DHCP pool lease timeout, misconfigured gateway IP, DNS server unreachable, or static rogue IP overlap.

Diagnostic Procedure: Executed ipconfig /all; observed APIPA 169.254.x.x on rogue laptop and identical static IP lease conflict. Ran nslookup google.com which timed out on DNS 127.0.0.1 loopback.

Solution: Flushed local DNS resolver cache (ipconfig /flushdns), released and renewed DHCP lease (ipconfig /release && ipconfig /renew). Reconfigured router DHCP scope from /24 to /23 with 2-hour lease duration to avoid pool starvation.

Lesson Learned: Always segregate guest mobile clients from administrative static nodes via isolated VLANs with aggressive DHCP lease expiries.

Problem: Severe 60Hz low-frequency electrical hum and buzz reverberating through auditorium line-array speakers when laptop audio was plugged into the analog console.

Possible Causes: Ground potential differences between laptop power brick and amplifier outlet; unbalanced 3.5mm line input; unshielded cables parallel to stage lighting mains.

Diagnostic Procedure: Isolated input channels one-by-one on the mixing board. Disconnecting the laptop charger instantly silenced the hum, identifying an AC ground loop circuit.

Solution: Routed laptop audio through a passive Stereo Direct Injection (DI) box with galvanic ground-lift switch engaged. Re-routed signal cables perpendicularly away from stage lighting dimmers.

Lesson Learned: Never feed consumer unbalanced audio directly into live stage preamps without galvanic isolation and balanced XLR conversions.

Problem: College laboratory PC halted during POST with blue screen error 0xc0000098: The Windows Boot Configuration Data does not contain a valid OS entry.

Possible Causes: Sudden power outage during scheduled system patch update, corrupted EFI system partition, or SATA SSD read sector glitch.

Diagnostic Procedure: Booted via laboratory Windows PE recovery flash drive. Inspected disk structure using diskpart; confirmed volume C: and FAT32 100MB EFI partition were intact but unindexed.

Solution: Assigned letter to EFI volume in diskpart. Executed bcdboot C:\Windows /s S: /f UEFI to regenerate a clean BCD store. Re-ran chkdsk C: /f /r to repair dirty sectors.

Lesson Learned: Bootloader rebuilds avoid destructive OS reinstalls, saving student project data and preserving lab configuration profiles.

Problem: Student registration web app threw intermittent HTTP 500 / OperationalError: (2006, 'MySQL server has gone away') during concurrent submissions.

Possible Causes: Unclosed cursor instances leaking connections, max_connections ceiling reached, or firewall terminating idle socket connections without keep-alive.

Diagnostic Procedure: Audited MySQL server metrics via SHOW STATUS LIKE 'Threads_connected'; which hit the default 151 limit. Reviewed backend code and discovered raw connections created per request without pooling.

Solution: Implemented a managed Connection Pool (pool_size=20, max_overflow=10) with automatic ping recycling (pool_recycle=3600). Wrapped DB sessions in context manager try...finally: session.close().

Lesson Learned: Always manage database connections with thread-safe pooling to handle burst traffic and avoid connection exhaustion.

Problem: IT lab workstation powered on with spinning fans and LED indicators, but showed black screen with no POST and 3 distinct recurring motherboard beeps.

Possible Causes: Unseated RAM stick, oxidized DIMM golden contacts, failed memory channel, or static discharge damage.

Diagnostic Procedure: Consulted AMI BIOS beep code manual (3 short beeps = first 64KB memory failure). Extracted both 8GB DDR4 sticks; tested each individually across Channel A and B slots.

Solution: Cleaned oxidized gold pins using 99% isopropyl alcohol and anti-static microfiber. Slot A had accumulated dust cleared with compressed air. Reseated module in Slot A2; PC immediately completed POST and passed MemTest86 with 0 errors.

Lesson Learned: Systematic single-component isolation saves expensive motherboard replacements caused by minor surface oxidation.
Cybersecurity Case Study

SQL Injection (SQLi) Vulnerability & Defensive Mitigation

OWASP Top 10 A03

Flaw Mechanics: SQL Injection happens when untrusted user input is directly concatenated into dynamic SQL queries without syntax escape. An adversary can input malicious payloads such as ' OR '1'='1 to manipulate query logic, bypass authentication, extract confidential data, or execute administrative commands.

# HIGH RISK: Raw string interpolation allows attacker authentication bypass
def authenticate_user(user_input, password_input):
    # ATTACK VECTOR: If user enters: admin' --
    # The resulting SQL executes: SELECT * FROM users WHERE username = 'admin' --' AND password = '...'
    query = f"SELECT * FROM users WHERE username = '{user_input}' AND password = '{password_input}'"
    
    cursor.execute(query)  # <-- VULNERABLE: Direct interpreter execution
    return cursor.fetchone()
Risk Assessment: Complete database dump, privilege escalation to admin role, and data tampering.
# SECURE: Prepared statements with bound parameterized placeholders
def authenticate_user_secure(user_input, password_input):
    # DEFENSE: Parameter placeholders (%s) enforce strict data-plane typing.
    # The database engine treats payloads purely as string literals, not executable SQL syntax.
    query = "SELECT user_id, username, password_hash, role FROM users WHERE username = %s"
    
    cursor.execute(query, (user_input,))  # <-- SECURE: Bound Parameter
    user = cursor.fetchone()
    
    if user and verify_bcrypt_hash(password_input, user['password_hash']):
        return user
    return None
Defense in Depth: Uses parameterized queries + Bcrypt hash verification. Input validation and least-privilege DB user accounts complete the defense.

Senior BSIT Culminating Essay

From Theory to the Soundboard: My Evolution as a Technologist

When I first entered the Bachelor of Science in Information Technology (BSIT) program at Datamex College of Saint Adeline, technology felt like a vast labyrinth of discrete concepts. Textbooks cleanly demarcated software development from hardware engineering, and network topologies were portrayed as static diagrams on whiteboard lectures. Yet as I progressed into my senior year, that theoretical compartmentalization dissolved into a profound realization: real-world information technology is an interconnected, living ecosystem where hardware stability, network reliability, algorithmic logic, and human operation must harmoniously converge.

My greatest technical crucible arrived not within the serenity of an exam hall, but in the high-stakes pressure cooker of campus operations. Serving as the Official Event Lead Technical and Student Assistant from August 2024 to the present transformed my perspective on engineering. Standing behind an audio-visual console and patch bay during major collegiate symposiums with hundreds of eyes watching taught me that failure is immediate and unforgiving. When unexpected ground loops generate ear-piercing 60Hz hums minutes before an institutional guest speaks, or when a critical auditorium workstation throws a bootloader failure, abstract textbook memorization cannot help you. Only methodical diagnostics, cool-headed composure under pressure, and deep root-cause analysis can solve the problem.

This operational agility fundamentally shaped how I approach software and systems engineering. When writing code—whether developing our AI-assisted IT help desk ticket system or querying relational MySQL logs for peak network telemetry—I view code through the lens of real-world survivability. I learned that an algorithm is only as good as its error-handling boundaries, and a database schema is only as dependable as its normalization and connection pooling safeguards. My experience troubleshooting hardware, diagnosing DDR4 RAM faults, and untangling VLSM subnets directly informs my defensive programming mindset today.

Furthermore, my journey has solidified my philosophy surrounding modern artificial intelligence. In an era where AI tools are ubiquitous, true competence does not mean passive delegation. As evidenced by my AI literacy log, I treat generative tools as an intellectual collaborator that accelerates ideation, but demands rigorous human verification, benchmarking, and security audits. Knowing why a parameterized SQL query neutralizes injection attacks is infinitely more valuable than blindly generating code without comprehending its security implications.

As I look ahead to completing my BSIT degree in July 2027 and stepping into entry-level roles as a Network Engineer, Data Analyst, Web Developer, or IT Support Specialist, I carry more than technical syntax and academic honors. I bring an battle-tested resilience forged in live event production, a relentless curiosity for systems architecture, and an unwavering commitment to continuous learning. Technology will inevitably evolve, but the core discipline—diagnosing rigorously, engineering thoughtfully, and communicating clearly—remains my steadfast foundation.
